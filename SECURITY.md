# Sicherheitslücken melden / Reporting security issues

**English below.**

Bitte **nicht als öffentliches Issue**. Nutze auf GitHub den Reiter **Security** und dort **Report a vulnerability**. Die
Meldung bleibt vertraulich, bis es eine Behebung gibt.

Schreib hinein, was passiert, wie man es auslöst und welche Fassung betroffen ist (unten links auf der Seite). Keine echten
Schlüssel, Passwörter oder privaten Daten mitschicken.

| Besonders wichtig | Beispiel |
|---|---|
| Zugriff ohne Schlüssel | Daten lesen oder ändern ohne Anmeldung, Geräte-Schlüssel darf mehr als melden |
| Fremder Code | Eine Seite, Notiz oder Datei bringt Skripte in die Oberfläche oder Befehle auf den Rechner |
| Datenverlust | Aufräum-Werkzeuge entfernen etwas, das sich nicht neu erzeugt |
| Agenten steuern | Text von außen bringt die Agenten dazu, gegen `REGELN.md` zu handeln |

Geprüft wird nur die neueste Fassung auf `main`. Das Projekt wird in der Freizeit gepflegt, eine feste Antwortzeit gibt es
nicht.

## English

Please **don't open a public issue**. On GitHub, use the **Security** tab and then **Report a vulnerability**. The report stays
confidential until there is a fix.

Say what happens, how to trigger it and which version is affected (bottom left of the page). Don't send real keys, passwords or
private data.

| Especially important | Example |
|---|---|
| Access without a key | Reading or changing data without logging in, a device key that can do more than report |
| Foreign code | A page, note or file brings scripts into the interface or commands onto the computer |
| Data loss | Tidying tools remove something that doesn't regenerate |
| Steering agents | Outside text makes the agents act against `REGELN.md` |

Only the latest version on `main` is checked. The project is maintained in spare time, so there is no fixed response time.
